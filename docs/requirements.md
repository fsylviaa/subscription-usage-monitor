# iPhone 订阅额度监控需求文档

版本：0.8。建立日期：2026 年 10 月 8 日；最近校订：2026 年 10 月 10 日。

本项目开发一款 iPhone App，让用户连接自己已有的 OpenAI 账户，自动查看 **Codex 订阅剩余额度**、重置时间，并通过桌面小组件和重置提醒减少主动查询的操作。**当前 MVP 只做 Codex，支持多个 Codex 账户。** 用户口述的“GPT 账号”指这里的 OpenAI 账户，不新增 ChatGPT 聊天额度或 OpenAI API 余额功能。

本文规定功能、用户体验和验收；[首版平台登录与额度连接方案](首版平台登录与额度连接方案.md)规定技术研究与接入依据。技术方案已按用户最新确认同步范围、刷新和重新登录规则，保留 13 平台研究证据；其他 12 个平台用于后续扩展，不是 MVP 必须交付的清单，也不表示已完成 iPhone 接入。后续若有差异，以用户最新明确决定为准。

本轮仅更新需求、连接技术方案、决定记录及项目说明，不修改 Figma，不编写或接入 App／后端。已有原型、历史验收和参考代码均不代表本文新增行为已实现。

## 1. 产品目标与核心原则

### 1.1 使用场景

- 打开 App 就查看自己的 Codex 剩余额度与重置时间，无需先手动刷新。
- 有多个账户时，在同一列表分别查看，并按自己的习惯调整顺序。
- 从主屏幕小组件查看列表首个账户的周额度和 5 小时额度。
- 在已知的预计重置时间收到提醒，是否开启由用户决定。

### 1.2 能简化就简化

此原则同时约束需求、设计和开发，项目级规则见 [AGENTS.md](../../AGENTS.md)。

- 用户需要结果，不需要理解额度接口、凭据、后台任务或技术错误分类。默认自动完成可以自动完成的事，减少步骤、设置、说明和打断。
- 网络评分不达标时显示简短的“网络不达标，无法更新”；其他刷新失败统一显示“刷新失败”，可建议“可尝试重新登录”。不展示技术错误码、长原因或排查清单，不要求用户判断故障类别。
- 简化对外提示不改变内部正确性：检查未通过不查询；失败不伪造额度，不改写最后成功时间；重新登录是可选恢复操作，不保证解决所有失败。
- 明确功能、信息、流程和状态即可。颜色、间距、精确尺寸、动画时长等不在本轮写死，后续设计和开发可调整。
- 不为假想边界增加设置、复杂选择器或额外页面。未纳入本版的能力留到后续讨论。

### 1.3 名词

“订阅额度”是 Codex 订阅实际提供的额度窗口，不是手机网络流量、历史 token 统计或 API 账单余额。“连接账户”是允许本 App 查询用户已有账户，不是注册本产品账户。“小组件”指 iPhone 主屏幕小组件；“锁屏通知”不等于锁屏小组件。

## 2. MVP 范围与扩展边界

### 2.1 第一版包含

| 编号 | 功能 | 范围 |
|---|---|---|
| S-01 | iPhone App | 第一版只做 iPhone，以 App Store 发布为目标 |
| S-02 | Codex 多账户 | 连接已有 OpenAI 账户，查看 Codex 订阅额度；可继续添加不同账户 |
| S-03 | 额度看板 | 每账户独立卡片，显示剩余额度、窗口、重置时间与成功更新时间；可调整账户顺序 |
| S-04 | 桌面小组件 | 小号和中号均提供；统一展示当前账户列表首个账户的周额度和 5 小时额度 |
| S-05 | 额度重置提醒 | 一个全局开关，按有效重置时间安排本地提醒，支持系统允许的锁屏展示 |
| S-07 | 小组件添加教程 | 首页和设置可进入两步教程，配简单教学动画，无需选择组件账户 |
| S-08 | 系统外观适配 | App 和小组件自动跟随浅色／深色，采用简洁黑白灰卡片方向 |
| S-09 | 查询前网络检查 | 新增账户前及每次实际额度查询前检查指定评分，只有有效评分大于 50 才继续 |
| S-10 | 自动更新 | 打开／回到 App 自动刷新；后台以每 30 分钟尝试更新一次为目标；保留手动刷新 |

### 2.2 第一版不包含

- Codex 以外的平台接入；13 平台的技术研究不自动成为当前功能范围。
- 独立 ChatGPT 聊天额度、OpenAI API 余额、购买或管理平台订阅、AI 对话。
- 本产品自己的注册登录、电脑端 App、电脑采集器、电脑日志上传或 Tokens.ci 接入。
- 历史 token、费用、趋势、排行榜、小票分享或打印音效。
- 产品体验演示模式、独立 App 内小组件预览页、小组件账户选择或小组件内多个账户同屏。
- 锁屏小组件、实时活动、低额度预警、iCloud 同步、iPad／Mac 版本、内购或 Pro 权益。
- 用户设置刷新间隔、手动选择浅深主题、切换“已用／剩余”视角。

### 2.3 保持可扩展性

技术上沿用“一套账户与额度框架，各平台独立接入模块”的方向，复用已有平台查询能力及技术方案中的研究成果。账户识别、排序、快照、刷新、通知、小组件等公共能力不能与 Codex 写成不可分离的一套，数据需保留平台归属和真实窗口含义，方便以后增加平台。

MVP 只注册和展示 Codex，不提前暴露其他平台入口、密钥输入或配置页面，也不把现有 13 个平台全部集成作为本轮完成条件。后续平台可能采用不同单位、窗口或登录方式，相关产品展示另行确认，不直接套用 Codex 的两个窗口。

优先手机直接访问平台、无需自建业务后端；新增网络评分服务仍按第 4.8 节使用。具体接口、凭据续期、系统调度和平台兼容性留在技术方案及实现验证中，不要求用户处理。若 Codex 手机接入存在无法满足当前体验的实质限制，再带证据讨论，不自行引入电脑或扩展安装流程。

## 3. 页面与主要流程

第一版主要入口为“额度”和“设置”。

| 页面／入口 | 用户能做什么 |
|---|---|
| 无账户页／连接入口 | 开始连接 Codex；无需在多个平台之间选择 |
| 平台登录 | 在系统默认浏览器完成 OpenAI 必要的登录／确认，返回 App 后自动继续 |
| 额度看板 | 查看所有账户独立卡片，自动更新或手动刷新，展开套餐及详细更新时间，调整账户顺序 |
| 账户操作 | 对指定账户刷新、重新登录或断开连接 |
| 设置 | 管理账户、重置提醒，进入小组件教程、帮助、隐私和开源许可 |
| 小组件教程 | 学习添加小号／中号组件；组件自动显示列表首个账户 |
| 系统小组件 | 查看首个账户两类额度，点击进入该账户的额度内容 |

主要流程：

1. 连接 Codex → 新增前检查网络 → 通过后在默认浏览器完成授权 → 回 App 自动继续 → 验证身份和凭据 → 首次查询前检查 → 显示真实额度。已有有效绑定但未取得额度时保留账户并显示“尚未获取额度”，不伪装成查询成功。
2. 添加不同账户 → 追加到列表末尾；用户可移动顺序。重复账户及重连换账户按 ACC-10～11 处理。
3. 打开／回到 App → 自动刷新现有账户，与后台 30 分钟周期独立；不要求先点刷新，也不因后台刚更新过而跳过本次前台更新。
4. 后台获得执行机会 → 检查网络 → 自动查询 → 更新成功快照并请求小组件更新；失败保留旧数据，不弹出打断用户的窗口。
5. 添加小组件 → 自动显示当前列表首个账户；排序、移除或替换账户后同步该规则，无需单独配置。
6. 开启提醒 → 申请系统通知权限 → 按有效预计重置时间安排提醒；点击通知进入对应账户并自动更新。

## 4. 功能与验收要求

下列编号为当前功能依据；与旧版本同编号的历史验收记录不表示本版行为已验证。

### 4.1 连接与账户管理

| 编号 | 要求 | 验收条件 |
|---|---|---|
| ACC-01 | 只提供 Codex 连接 | MVP 只有 Codex；已有账户也能继续添加，不增加本产品注册 |
| ACC-02 | 使用已有平台账户 | 优先系统默认浏览器，尽量复用官网已有登录；不要求换浏览器、装扩展、导出 Cookie、创建 API key 或安装电脑工具；平台所需登录／验证码由官网处理 |
| ACC-03 | 连接状态准确 | 区分等待用户授权、用户取消、连接未完成、身份／凭据验证通过及额度已获取；界面用简短状态，不展示内部阶段或技术错误；仅打开网页或返回 App 不算连接成功 |
| ACC-04 | 账户身份常显 | 卡片和账户列表显示可辨认的账户标识，优先可靠邮箱；无法取得的姓名／套餐不编造；用户不用展开就能区分账户 |
| ACC-05 | 日常免重复登录 | 保存有效授权，能够自动续期时自动处理；关闭浏览器或重开 App 后继续查询。失败保留有效连接及旧数据，用户可重新登录，不强制每次刷新先登录 |
| ACC-06 | 断开指定账户 | 经明确操作移除本 App 中该账户凭据与共享数据、取消待发提醒；请求组件采用新的列表首个账户，无账户时显示规定空态。不取消平台订阅或清除其他客户端登录 |
| ACC-07 | 账户之间不串数据 | 单账户刷新、重登、取消和断开不改其他账户；ACC-10～11 明确的重复账户替换是例外；已取消或旧登录的迟到结果不能恢复旧账户或覆盖新身份 |
| ACC-08 | 支持多个 Codex 账户 | 不同账户各有一张卡片，同页查看，不要求切换当前账户才能看到；没有原型样例数量限制 |
| ACC-09 | 新增前检查 | 新增前网络检查未通过，不进入实际授权、不产生新账户；取得有效绑定后的首次额度查询仍受 NET 规则约束 |
| ACC-10 | 重复登录采用最新结果 | 同平台同邮箱视为重复连接，不弹“账户已存在”，只保留一条。新身份和凭据验证成功后替换旧连接，取消或登录失败不先删除旧记录；新连接以自身有效身份和作用域查询，不混用旧凭据 |
| ACC-11 | 重新登录采用实际身份 | 原来是账户 1，再登录账户 1 就更新原连接；登录账户 2 就直接显示账户 2，不增加身份差异确认或阻止。若新身份已存在，则去重为一条最新连接；被替换身份的额度和提醒不沿用到另一身份 |
| ACC-12 | 按添加顺序并可调整 | 不同新账户追加末尾，不按平台重新分组；提供简单移动排序能力，保存后重启仍保留，额度页、账户管理及组件使用同一顺序。从添加入口重复登录时更新已有行并保留位置；从某行重连时保留该行位置，若命中另一已有账户则移除另一重复项，其余账户相对顺序不变 |
| ACC-13 | 首次未取得额度可继续恢复 | 已取得并验证有效绑定后，首次检查或额度查询失败仍保留该账户，显示“尚未获取额度”，允许重试或重新登录；未取得真实值前不显示假百分比、假重置时间或成功时间 |
| ACC-14 | 浏览器往返简洁 | 如采用技术方案中的一次性代码，提供代码、复制和打开官网入口；返回 App 后自动继续有效登录流程，无需“我已登录”确认，不重复要求选择账户或申请代码；取消则停止本次流程，到期或失败可重新开始 |

去重依据是同平台可靠邮箱；内部仍保留新登录的服务端账户和作用域标识，以保证取到的是用户本次选择的额度，不能把两个工作区的数据相加或串用。无法可靠识别身份时不能误删其他记录。新绑定尚未取得额度与完整“连接并可查询”的验收是两回事，后者仍需真实查询成功。

### 4.2 额度看板与更新

| 编号 | 要求 | 验收条件 |
|---|---|---|
| QTA-01 | 每账户独立卡片 | 不合并不同账户额度，常显账户身份、真实窗口和剩余值；可展开套餐和详细成功更新时间 |
| QTA-02 | 固定剩余视角 | 数值和标签显示剩余；进度条左侧实色为已用、右侧灰色为剩余；不提供视角切换 |
| QTA-03 | 显示重置时间 | 有真实时间时显示可理解的时间／倒计时；没有则简短显示“未提供重置时间” |
| QTA-04 | 只展示真实额度 | Codex 以周和 5 小时窗口为主要展示项，按真实数据标识；未提供或未取得的字段不编造，不拿其他窗口或 API 余额冒充；技术方案中的 credits 等附加指标不是 MVP 必做功能 |
| QTA-05 | 打开即自动更新 | 启动或从后台回到 App 时独立自动刷新全部已绑定账户，不因缓存较新而要求用户手动触发；先显示可信缓存，更新轻量进行，无需阻塞整个页面。浏览器登录返回按 ACC-14 恢复，新账户不被重复创建 |
| QTA-06 | 显示最后成功时间 | 每账户成功快照有时间；失败不能改写。顶部条隐藏后仍可在账户详情查看 |
| QTA-07 | 失败保留数据 | 有可信缓存则继续显示原值和原时间；没有则显示“尚未获取额度”，不能当作 0% 或 100%；关闭提示不代表数据恢复 |
| QTA-08 | 简化失败反馈 | 有效评分不达标显示“网络不达标，无法更新”；其余刷新失败统一“刷新失败”，可附“可尝试重新登录”。提供重试和已有账户的重新登录入口，不罗列技术原因、不要求判断故障类别 |
| QTA-09 | 到重置时间不自行改满 | 倒计时到点只表示预计重置，等待真实查询，不自行把余额改成 100% |
| QTA-10 | 保持真实计量含义 | 不限量、未知额度和没有可信限额的情况不画假百分比；内部保留单位和窗口语义，不能靠界面推算账户总余量 |
| QTA-11 | 保留简洁顶部操作 | 刷新和连接位于“订阅额度”标题右侧同一行；无提示用户点击刷新才能看最新额度的说明 |
| QTA-12 | 点击主动刷新 | 用户点击时触发主动刷新：顶部刷新作用于全部账户，卡片刷新只作用于该账户；重试沿用原范围。部分账户失败时成功账户照常更新，失败账户保留旧值；顶部按 QTA-08 显示简短提示，不新增详细错误汇总页 |
| QTA-13 | 成功隐藏结果条 | 本次范围全部查询成功后立即隐藏顶部整条信息，无需点击或等待；仅检查通过不是查询成功 |
| QTA-14 | 失败条可关闭 | 本次范围网络检查未通过或查询失败时，保留对应简短失败条及重试，提供易点的右上角“×”；不展示技术原因清单，不自动消失 |
| QTA-15 | 隐藏后收紧布局 | 整条信息与按钮一起隐藏，列表自然上移，不留占位；只隐藏提示，不修改数据、原时间和账户状态 |
| QTA-16 | 新一次更新采用新结果 | 成功隐藏、失败显示；已关闭的同一次提示不因切换页面重现；重新登录入口指向具体账户，不能误替换其他账户 |
| QTA-17 | 更新中不以关闭条取消 | 顶部更新中的信息条不提供关闭按钮；用户取消尚未执行的网络检查／登录，走该流程的取消操作，见 NET-09 |
| QTA-18 | 每半小时被动刷新 | 后台以每 30 分钟尝试刷新全部已绑定账户为目标，网络检查通过才查询；这是系统允许时尽力执行的目标，不依赖持续常驻，不承诺关闭 App 后准点执行。不给用户增加频率设置 |
| QTA-19 | 前台与周期独立 | 打开 App 的刷新不等待下一次 30 分钟周期，也不被刚完成的后台刷新免除；同一时刻已有相同账户刷新进行中可复用，避免重复并发。后台失败不自动打开登录页或弹窗，等待后续自动更新或用户操作 |

进度条在 App、小号／中号组件及浅深外观中含义一致：剩余 70% 对应左侧 30% 实色、右侧 70% 灰色；剩余 100% 时全条剩余底色，0% 时全条已用实色。未知或不限量不绘制虚假比例。具体刷新请求合并、续期和重试退避属于技术实现，不向用户增加操作。

### 4.3 桌面小组件

| 编号 | 要求 | 验收条件 |
|---|---|---|
| WGT-01 | 小号和中号均交付 | 两种尺寸均能在系统中找到、添加并正常使用，不能只验收一种或只提供 App 内图片 |
| WGT-02 | 固定当前首个账户 | 所有组件实例自动显示当前账户列表第一个账户；不提供单独选账户／编辑账户配置；不同时显示多个账户。用户调整 App 排序即决定组件展示哪个账户 |
| WGT-03 | 展示两个主要窗口 | 同一个账户的每周和 5 小时额度均可显示；显示账户标识、窗口名称、剩余值、进度条、重置时间及最后成功更新时间。小号纵向排两个窗口，中号利用空间清楚展示；未提供的窗口不伪造，也不加入更多窗口选择器 |
| WGT-04 | 与 App 使用同一份结果 | 组件读取对应账户最近成功的额度快照，字段含义与 App 一致；正常、更新和失败状态都能辨认数据新旧；不因不同尺寸改成不同账户或不同含义 |
| WGT-05 | 点击进入对应内容 | 打开组件当前展示账户的额度内容并触发前台自动刷新；系统仍显示旧画面时，旧账户存在则进入该账户，已移除则进入当前有效额度页／无账户连接引导，不恢复删除数据 |
| WGT-06 | 无账户或无数据 | 无绑定账户时显示“未连接账号，无数据”；首个账户已绑定但无额度时显示“尚未获取额度”，不擅自跳过它改显示后面的账户，不出现“请选择账户”状态 |
| WGT-07 | 自动更新与失败保留 | App 自动／手动查询成功后保存共享结果并请求系统更新；组件不要求用户另点刷新、不建立独立用户配置的查询周期。失败保留同一账户可信旧额度与原时间，必要时仅用简短失败提示 |
| WGT-08 | 跟随列表变化 | 首项因排序、断开或账户替换发生变化时，准备新首项的身份、该账户自己的额度及点击目标并请求所有组件更新；不再采用“同平台优先”或保留每个组件单独选择的旧规则。列表为空则使用规定空态 |

后台 30 分钟目标用于自动获取供 App 和组件共同展示的数据，实际后台查询与组件画面更新由 iOS 调度，允许存在延迟；不承诺瞬时切换或严格半小时刷新。断开／替换时及时清理不再使用的共享身份和数据，不将旧账户额度带到新首项。锁屏小组件及多账户组件留待后续。

### 4.4 通知与锁屏提醒

| 编号 | 要求 | 验收条件 |
|---|---|---|
| NTF-01 | 一个全局重置提醒开关 | 对全部已绑定账户生效，新增账户沿用当前开关；不开启也能使用额度看板和组件，无额外分账户通知设置 |
| NTF-02 | 主动开启时申请权限 | 拒绝后只提供必要的系统设置入口，不反复打断；回 App 后反映真实权限 |
| NTF-03 | 根据已知时间安排 | 开关开启且系统许可时，按账户的真实有效预计重置时间安排本地提醒；无时间不编造、不安排 |
| NTF-04 | 支持系统锁屏展示 | 在系统允许条件下显示，尊重用户的锁屏和专注设置，不承诺强制弹出或秒级到达 |
| NTF-05 | 简短且识别对应窗口 | 能区分账户和额度窗口，表达“预计重置，打开查看”；未查询确认不能宣称余额恢复 100% |
| NTF-06 | 更新与取消 | 重置时间改变时更新；关闭开关、断开或替换掉某身份时取消其未触发提醒，按新身份有效数据安排 |
| NTF-07 | 不重复提醒 | 同账户、同窗口、同轮重置不因重复刷新或重复登录多次提醒；模拟数据不发真实通知 |
| NTF-08 | 点击进入具体账户 | 打开通知对应账户并自动更新；账户已被移除／换成另一身份时进入当前有效状态，不把旧通知当成另一账户的通知 |

第一版采用已知时间的本地重置提醒，不要求服务器推送、低额度阈值预警或额外后台通知。账户排序不改变提醒归属。

### 4.8 网络检查与简短提示

保留指定来源 [Net.Coffee 检测页面](https://ip.net.coffee/claude/) 的 Claude AI 信任评分作为内部前置规则。来源名称不意味着 MVP 新增另一平台；MVP 连接与查询仍只有 Codex。

| 编号 | 要求 | 验收条件 |
|---|---|---|
| NET-01 | 指定来源 | 使用上述来源的评分，不自行换成普通网络连通性或其他分数 |
| NET-02 | 有效评分必须 > 50 | = 50、< 50 或无法取得有效评分时均不继续；检查通过也不等于登录或额度查询成功 |
| NET-03 | 新增前检查 | 在实际新增授权前执行，未通过不建立新账户；重连按相同连接前检查规则处理 |
| NET-04 | 全部实际查询遵守 | 首次查询、手动全部／单账户刷新、打开 App、后台周期、通知或组件打开、重新登录后的查询、重试都执行检查，不通过其他入口绕过 |
| NET-05 | 无有效结果不伪造 | 超时、服务不可用、评分缺失或无效都阻止操作；内部保留必要类别，对外更新统一“刷新失败”，不把未知评分伪装成有效低分，不展示技术原因 |
| NET-06 | 有效低分简短提示 | 更新时“网络不达标，无法更新”；连接前用“网络不达标，无法连接”。不要求展示具体分数、阈值或技术解释，保留原账户和可信数据 |
| NET-07 | 重试重新检查 | 保持原操作和账户范围；仅成功查询才能写入新额度及成功时间；其他刷新失败按 QTA-08 提示，连接未完成简短显示“登录未完成，请重试” |
| NET-08 | 轻量自动继续 | 前台只展示必要的连接／更新中反馈，通过后自动继续，不要求用户额外点“通过”；正常刷新不额外增加评分介绍页 |
| NET-09 | 可退出且不打扰 | 用户取消实际授权／查询开始前的检查或登录时停止本次后续操作，迟到结果不再自动发起；按来源返回。后台更新不弹前台窗口。关闭已完成的失败条只隐藏提示，不清数据、不撤销已完成结果 |

查看缓存、展开详情、倒计时和按已知时间显示预计重置通知不是新联网查询，不额外检查。评分及内部错误区分用于正确处理，不自动成为需要给普通用户展示的信息。

## 5. 数据与隐私

仅保存查询需要的本 App 授权、账户身份与顺序、最近成功快照及用户设置。凭据安全保存在本机，不进入普通日志、示例截图或仓库；小组件仅取得必要信息，不额外收集用户资料。

每份额度至少区分平台、实际账户／作用域、窗口、数值及单位、限额和重置是否已知、最后成功时间及当前状态。内部准确性不能因为简化用户提示而丢失。新登录、断开或替换后的迟到请求不能串入另一账户，也不能恢复已删除的数据。

不采集电脑聊天、代码或会话日志；不上传 Tokens.ci。断开只移除本 App 的连接与数据，不取消订阅、退出全部浏览器或破坏电脑已有登录。重复登录替换的是本 App 旧记录，不操作平台上的账户或订阅。

| Codex 手机授权与持续查询 | 按技术方案验证默认浏览器、授权恢复、正确身份、续期、真实额度和独立发布条件；失败不擅自改为 API 余额或电脑辅助 |
| 后台与组件更新 | 在目标 iOS 上验证约 30 分钟目标、进入 App 独立更新和系统延迟，不承诺后台常驻 |
| 网络检查 | 验证指定评分取得、实际查询网络和请求调度；不改变 > 50 阈值，不扩大用户错误说明 |
| 套餐与返回字段 | 以 Codex 真实支持和可可靠获取的窗口验收，无数据不补造；附加额度不自动纳入 MVP |
| 名称、图标、最低 iOS、视觉细节 | 在设计／工程阶段确定，保留简洁卡片和浅深一致性 |
| 上架地区、语言、商店与隐私材料 | 发布准备时确认；暂按已有开发者账号规划，会员状态届时核实 |
| 其他平台与更多组件能力 | 技术保持扩展，新增交付范围另行确认，不要求现在完成 13 平台 |
