## 用户怎么验收

用户已完成下述两步，并明确确认“两步都符合预期”，**无需重做**。下列步骤保留作为验收依据，本次独立验收材料已清理。

1. 在当前代码页点 **复制代码 → 打开官网**，先不完成确认。在浏览器停留片刻，或锁屏再解锁，然后回到“订阅用量”。应仍显示原代码并继续等待，不要求重新选择平台或点“我已登录”。
2. 再点 **打开官网**，由本人完成账户登录和代码确认，然后回到 App。应自动出现 **一条本人邮箱**，并显示 **尚未获取额度**，无需再点连接。

## 本次实现

- 原设备事务保留最初开始与到期时间；启动自动读取，不因重开延长期限或重新申请。
- 等待授权继续领取；已安全保存但尚未兑换的结果只交换一次；已有待验证令牌只做核验。后台不开始新的领取／交换／核验／保存步骤，回前台由原工作继续，不承诺后台常驻。
- 兑换前先持久记录“已开始”，再发请求。结果不明且没有已保存令牌时简短失败，重新开始，不重复消费单次代码。旧 T09 codeReceived 同样保守处理。
- 恢复合并重复启动／回前台事件；新进程恢复与重试仍执行既定网络检查，不把回到 App 或读到令牌当成功。
- 取消先写无秘密的取消标记，阻止迟到保存复活；冷启动清理残留。读取期间取消也会清理迟到读回的原事务；暂不可读而未知事务 ID 时，先完成安全取消才关闭，无法确认时保留简短失败。
- 已提交账户优先于残留临时事务，不重复建账户。永久坏阶段可清理重试，存储暂不可用保留原内容；不改动现有正式账户、顺序或授权。
- 仅 T10 范围，没有修改 Figma，没有接入额度、续期、多账户或 T27 的正式账户前台刷新。
