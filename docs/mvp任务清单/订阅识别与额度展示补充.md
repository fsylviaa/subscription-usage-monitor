# 0.9 订阅识别与额度展示：任务补充

确认日期：2026-10-10。依据：[需求 0.9 第 4.11 节](../requirements.md#411-动态订阅资料与额度适用性)、[决定 D-51～D-54](../decisions.md)。本文件补充既有任务的验收，不增加首版平台、不表示代码已经实施。其他 0.8 任务范围和依赖继续有效。

## 所有相关任务共同遵守

- 使用当前账户从平台取得的套餐名称，标题为“平台 · 实际套餐”，中间是 U+00B7。Free、Plus 只是例子，不是套餐白名单；不写成“免费版”，不让用户逐个指定名称。仅有套餐标识时保留实际标识，不编造显示名称。
- 套餐取得、无本期适用额度、额度取得、获取失败各有明确结果。不能从空数组、缺字段、新名称或查询失败推断免费；套餐识别成功也不能冒充额度获取成功。
- Codex 可靠确认 Free 且无本期适用周／5 小时额度时，只显示身份和套餐，不出现额度、重置、假成功时间或失败占位。30 天窗口、credits、API 余额不加入本期。
- 首次获取失败显示“获取失败”；已有可信结果的刷新失败保留原数据及原时间并显示“刷新失败”。有效网络低分仍显示“网络不达标，无法更新”。旧任务中一概显示“尚未获取额度”的要求由此替代。
- 正常刷新同时更新套餐。确认套餐变化后旧额度不能挂在新套餐下，取消失效提醒；失败本身不证明套餐变化。组件固定首账户，不因其没有适用额度而跳过它。
- 套餐名称动态开放，不代表自动支持新平台或任意变化的接口；公共框架保留扩展，平台逐个按授权接入，不限于研究中的 13 个。

| T16、T18～T22 | 套餐与对应身份、作用域和凭据版本绑定；重连、替换、去重和迟到结果不串用资料或额度 |
| T23、T24 | 套餐常显，详情展示真实详细时间；无适用额度不保留空进度或重置占位。覆盖 Free、平台新名称和获取失败；套餐不再仅藏在展开详情内 |

| T48～T53、T55、T56 | 真机覆盖实际套餐、正常无适用额度、真实额度、失败恢复和组件／提醒一致性；新增名称和难复现套餐变化可隔离验证，真实与模拟分别记录；最终验收不能把旧版通过记录当新增规则已通过 |

## 新增验收场景

| 输入／操作 | 应当看到的结果 | 验证方式 |
|---|---|---|
| 平台确认当前账户名称 Free，且无本期适用窗口 | Codex · Free；只显示身份和套餐，不报失败、不造额度时间 | T12 真实账户核对，并以隔离输入覆盖状态 |
| 套餐与真实周／5 小时额度返回 | 实际套餐名称、正确剩余和真实时间；保存后读回一致 | T12 真实有额度账户 |
| 受支持字段返回此前未出现的套餐名称 | 原名称照常显示，处理实际适用额度，不要求改名称名单 | T12／T23 隔离场景 |
| 首次套餐取得，但应有额度查询失败 | 保留套餐并“获取失败”，不写额度成功时间 | T12／T13 隔离场景 |
| 套餐字段缺失、空响应或适用性无法确定 | 不默认 Free、不当作正常无额度；显示简短失败，保留可信旧资料 | T12／T13 隔离场景 |
| 正常查询结果为 0，或仅有一个真实窗口 | 真实零按零显示；部分字段保留真实含义，不把缺失伪造成无额度账户 | 沿用 T11，并在 T12／T23 复核 |
| 刷新失败后重开 | 同订阅可信旧值、原时间及套餐保留；没有假成功 | T15／T25／T50 |
| 成功确认套餐升级／降级或新名称 | 显示新资料，不将失效旧指标挂到新套餐；正常更新继续执行 | T25～T31／T50；难复现场景隔离验证 |
| 当前首账户确认无适用额度，后面账户有额度 | 两种组件均保持首账户身份及套餐，隐藏额度区域 | T32～T37／T51 |
| 套餐变化使旧重置窗口失效 | 不再安排该窗口，取消旧待发提醒 | T39／T40／T52；模拟数据不发真实通知 |

本文定义增补要求，不替代各任务验收结论。T12 的历史真实 30 天响应、原测试结果及动态套餐修复证据保留在[验收记录](记录/T12-验收.md)，实际进度以项目看板为准。
