## 开发说明（给执行者）

### 目录及职责的最低要求

下表是本期简单分工，执行时记录实际目录名；允许按 Xcode 的正常结构合并很小的目录，但职责和后续落点必须清楚。不创建大量空类、空服务或独立包来凑“完整结构”。

| 建议位置 | 负责什么 | 本任务处理 |
|---|---|---|
| Xcode 工程文件、共享 Scheme | 构建与运行入口、App 和测试目标 | 建立并验证，记录实际名称 |
| `Sources/App/` | App 入口、后续依赖组装和生命周期连接 | 建立可运行入口和最小根页面 |
| `Sources/Features/` | 额度、账户、设置、教程等页面 | 建立页面落点；具体页面归 T03 及后续任务 |
| `Sources/Domain/` | 公共账户、额度语义和必要接口 | 建立落点；具体模型与接口在 T04、T11 等任务实现 |
| `Sources/Providers/Codex/` | Codex 登录、请求和额度解析 | 明确落点；T07–T14 逐项接入 |
| `Sources/Services/` | 网络检查、连接/刷新协调、提醒等共用流程 | 明确落点；不预先做整套通用框架 |
| `Sources/Storage/` | 本地账户与快照保存、钥匙串 | 明确落点；T04/T05 起实现 |
| `Sources/Shared/` | App 与组件可共享的纯展示数据和必要格式化 | 明确边界；不得放登录秘密，实际共享由 T32 实现 |
| `Resources/` | 图标、样式资源与实际使用的许可资料 | 建立必要资源位置，不做正式品牌设计 |
| `Tests/` | 单元/集成测试、固定样例和测试替身 | 建立最小测试目标和样例存放约定；不加产品内调试页 |
| `Widgets/` | 未来小组件扩展 | 仅记录落点，目标与共享能力在 T32/T33 建立 |
| `docs/`、根 README | 需求、任务、结构和运行说明 | 保留现有资料并补开发入口，不重建历史 |

尚无源文件的必要目录可以用最少的占位说明纳入 Git；不需要为每个未来功能创建空文件。实际目录与 Xcode 中显示的位置要一致可追溯。

### 模块协作与依赖

- App 入口负责组装。页面调用必要业务能力；公共数据与接口不依赖具体页面或 Codex 实现。Codex 接入负责平台差异，存储负责本机读写；两者不反向依赖界面。
- 后续组件只读取必要共享结果，不依赖主 App 的页面、登录流程或钥匙串。目录分工不要求拆成多个 Swift Package，优先保持一个简单、可运行的工程。
- 当前优先使用系统能力：SwiftUI、Foundation 和测试框架；安全存储、后台任务、WidgetKit、系统通知按其任务引入。说明里区分“现在使用”和“后续使用”。
- 第三方库只在确有当前用途时加入；记录名称、用途、来源及锁定方式，并保存适用的依赖锁文件。参考 CodexBar 不等于把整个桌面项目作为依赖。
- 测试替身、样例账户与生产数据隔离；具体评分、授权或通知模拟随对应任务补，不在 T01 预建庞大测试平台。

根 README 写明：实际 Xcode/系统条件、打开哪个工程、选择哪个共享运行方案、如何选择模拟器并运行、怎样执行已有检查、结构说明的入口。真机操作留给 T02；不以发布证书、商店配置或隐含本机文件作为模拟器启动前提。

保留现有 Git 仓库及忽略规则，排除构建产物、个人 Xcode 状态、授权和签名秘密。参考[技术连接方案](../../首版平台登录与额度连接方案.md)第 3、17 章的公共能力与 Codex 接入边界，保持本任务只交付基础脚手架。
