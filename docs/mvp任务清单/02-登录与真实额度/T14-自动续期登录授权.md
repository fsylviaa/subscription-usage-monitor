## 本次交付

授权需要更新时由 App 自动处理，再继续查询；用户不用日常反复登录，续期失败也保留可信旧额度。

## 范围边界

- 只接入手机独立授权的自动续期与一次适用的查询恢复。
- 不管理电脑凭据，不自动打开登录页，不新增续期设置；跨两次自然到期的长期观察从本任务开始记录，由 T54 收口。

## 验收准备

- 准备由本 App 独立登录取得的真实授权和一次已成功额度快照；不读取或复制电脑的登录文件。
- 开发者提供“临近到期”“查询需续期后成功”“网络失败”“平台明确不能续期”“新凭据保存失败”隔离测试；不要求项目经理手改令牌或系统时间。

## 项目经理怎么验收

真实操作与隔离测试分开记录；开发者负责准备和运行具名测试，不让项目经理改代码、读网络日志。测试构建不新增正式产品页面。

| 步骤 | 操作 | 应该看到的结果 |
|---|---|---|
| 1 | 真实流程：关闭浏览器后继续使用现有账户查询。 | 继续使用本 App 已保存授权，身份和额度正确；不要求重新打开网页登录。 |
| 2 | 隔离测试：用可控时钟让授权进入需续期状态，然后触发查询。 | 自动更新授权并取得新额度，界面无需额外操作；开发者摘要显示续期一次、查询成功。 |
| 3 | 隔离测试：查询首次要求重新认证，可续期并重试。 | 自动续期后仅做一次适用重试；成功更新额度；无无限重试和重复授权窗口。 |
| 4 | 隔离测试：续期网络失败或新凭据无法安全保存。 | 显示“刷新失败”，旧额度与原成功时间保持；不把未保存的新版本宣布为有效连接。 |
| 5 | 隔离测试：平台明确表示授权不可继续使用。 | 保留账户及可信旧值，允许后续通过重新登录恢复；不自动打开官网，不声称重登能修复所有失败。 |
| 6 | 查看开发者提供的续期记录起点。 | 真实现有授权使用结果与隔离测试分开记录；两次自然到期未观察到时明确“待 T54 验收”，没有写成已通过。 |

## 开发说明（实施时阅读）

- [技术连接方案](../../首版平台登录与额度连接方案.md) §3.5、§4.3；参考 [CodexTokenRefresher.swift](/Users/iceflying/codex/订阅用量监控/reference/CodexBar/Sources/CodexBarCore/Providers/Codex/CodexOAuth/CodexTokenRefresher.swift) 与 [CodexOAuthExpiryPipelineTests.swift](/Users/iceflying/codex/订阅用量监控/reference/CodexBar/Tests/CodexBarTests/CodexOAuthExpiryPipelineTests.swift)，按已核实协议版本实现手机自己的刷新链，不能照搬桌面共享凭据所有权。
- 同一凭据的续期串行进行，令牌与过期信息原子保存后再发布；请求失败不一概删凭据，结果不明时不能反复重放可能已消费的旧 refresh token。
- 401 仅在适用时续期一次再查；每次实际额度查询仍走 T06，续期本身不能作为跳过评分的理由。当前实现的版本保护为 T22 复用。
- 把可控测试、真实已有授权查询、自然到期观察分别标注。T14 可在前两类通过后存档；T54 必须补足两次真实自然到期证据，未完成前不能宣称日常续期整体验收通过。

本任务只以本文件范围内的实现和验收判定完成；后续自然观察尚未发生时，将观察项记在 T54 的待验事项中，不阻塞已通过本任务的 Git 存档和其他开发，也不提前宣称 T54 已通过。
