# T22 阻止取消和旧请求写回账户

> 状态：未开始。本文件是开发任务计划，不代表功能已经实现或验收。

- 前置依赖：[T10 返回App后继续原登录流程](../02-登录与真实额度/T10-返回App后继续原登录流程.md)；[T18 重复添加账户时更新原连接](../03-多账户管理/T18-重复添加账户时更新原连接.md)；[T21 断开指定账户并清除本机连接](../03-多账户管理/T21-断开指定账户并清除本机连接.md)。
- 对应需求：[需求 0.8](../../requirements.md)：ACC-07、ACC-10。
- 执行边界：一次对话／一次提交交付本文件所述单一成果；遵循[执行约定](../执行约定.md)。

## 本次交付

取消、断开或重复添加更新连接后，即使旧请求稍后才返回，也不能把旧账户恢复出来或覆盖新身份和新数据。

## 范围边界

- 只统一补齐登录、查询和续期结果提交前的当前身份／版本检查。
- 不增加用户设置或错误提示；刷新按钮与前后台同时触发的请求合并由 T28 完成。本任务关注旧结果能否写回。

## 验收准备

- 开发者提供具名延迟场景，允许“先开始旧请求 → 完成取消／替换／删除 → 再释放旧结果”；项目经理只操作正常页面并核对结果摘要。
- 使用隔离测试构建避免操纵真实服务或大量重复登录；测试中的旧结果与新结果使用明显不同的账户和值。

## 项目经理怎么验收

真实操作与隔离测试分开记录；开发者负责准备和运行具名测试，不让项目经理改代码、读网络日志。测试构建不新增正式产品页面。

| 步骤 | 操作 | 应该看到的结果 |
|---|---|---|
| 1 | 隔离测试：开始添加 A，取消，再释放原登录的成功结果。 | 账户列表仍没有 A，不自动恢复流程；没有新有效绑定。 |
| 2 | 隔离测试：A 查询尚未返回时，从添加入口完成 A 的新连接；再释放旧连接的额度。 | 保留 A 的最新连接；旧请求的额度和时间不能覆盖新结果。 |
| 3 | 隔离测试：A 查询或续期尚未返回时断开 A，再释放旧结果。 | A 不重新出现；其本机授权和快照不会被旧结果重新写入。 |
| 4 | 隔离测试：同一账户已完成新的成功登录，再释放旧凭据的续期结果。 | 保留最新成功登录；旧续期不能覆盖新授权，后续查询仍用新连接。 |
| 5 | 每个场景后重开 App，并检查未操作的 C。 | 被拒绝的旧结果没有落盘；C 的身份、顺序、额度和成功时间保持。 |

## 开发说明（实施时阅读）

- [技术连接方案](../../首版平台登录与额度连接方案.md) §3.5–3.6：请求开始时绑定事务、凭据版本与账户 generation；写入凭据、账户或快照前重新比对当前版本和删除状态。
- 取消／删除／身份替换先使旧操作失效，再提交新状态；单凭取消网络任务不足以阻止已经返回但尚未落盘的结果。
- T14 的续期与重复添加提交使用同一账户串行提交边界，统一复用版本判断，不为每个入口各写不一致的补丁。
- 验收摘要列出“操作后期望身份 / 释放旧结果后实际身份与时间 / 重开后结果”；不暴露 token 或要求项目经理阅读网络日志。
