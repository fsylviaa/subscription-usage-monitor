# T20 重登另一账户时替换并去重

> 状态：未开始。本文件是开发任务计划，不代表功能已经实现或验收。

- 前置依赖：[T17 移动账户顺序并持久保存](../03-多账户管理/T17-移动账户顺序并持久保存.md)；[T19 重新登录同一账户](../03-多账户管理/T19-重新登录同一账户.md)。
- 对应需求：[需求 0.8](../../requirements.md)：ACC-10、ACC-11、ACC-12。
- 执行边界：一次对话／一次提交交付本文件所述单一成果；遵循[执行约定](../执行约定.md)。

## 本次交付

从某个账户重新登录成另一账户后，直接显示本次实际账户并保留原行位置；若另一账户已存在，则合并为一条最新连接。

## 范围边界

- 只完成重新登录换身份、原位替换与去重，清除被替换身份的快照归属。
- 不增加“身份不同是否继续”确认，也不阻止换号；组件与提醒的实际联动由 T35/T40 分别接入。

## 验收准备

- 准备真实 A、B 两个已有账户；多行位置场景由开发者以隔离账户 A、B、C、D 提供。
- 开发者准备“换身份验证失败”“成功换号但首次查询失败”场景；项目经理不需修改账户文件。

## 项目经理怎么验收

真实操作与隔离测试分开记录；开发者负责准备和运行具名测试，不让项目经理改代码、读网络日志。测试构建不新增正式产品页面。

| 步骤 | 操作 | 应该看到的结果 |
|---|---|---|
| 1 | 真实流程：在 A 行选择重新登录，官网确认 B，完成验证。 | 该行直接显示 B，没有身份差异确认；显示 B 自己的数据，绝不把 A 额度贴到 B 上。 |
| 2 | 隔离测试：列表 A、B、C，从 B 行重新登录一个未在列表中的 D。 | 结果为 A、D、C；D 使用原 B 位置，A 与 C 相对顺序不变。 |
| 3 | 隔离测试：列表 A、B、C、D，从 B 行重新登录已存在的 D。 | 结果为 A、D、C；原 D 重复行移除，只保留本次最新连接，原 B 行位置保留。 |
| 4 | 换身份流程中取消或让新身份验证失败。 | 仍保留原列表、原连接和原额度；不会提前删除 A/B 或另一已存在重复项。 |
| 5 | 隔离测试：换身份已验证成功，但新身份首次额度查询失败，再重开。 | 保留新身份和正确顺序；不得沿用被替换身份额度与成功时间；无新身份可信快照时显示“尚未获取额度”。 |

## 开发说明（实施时阅读）

- [技术连接方案](../../首版平台登录与额度连接方案.md) §3.3–3.5 与需求 ACC-10–12：一次提交完成目标行替换、重复行移除、其余顺序保持和新的身份／作用域绑定。
- 采用最新成功登录的凭据，保留原行位置；新登录未验证成功不修改旧行。去重只使用可靠邮箱，不能凭相似名字误删其他记录。
- 被替换身份的快照、待发提醒归属和在途写回版本须失效；本任务处理已存在的账户数据并发出明确身份替换事件，T35/T40 接上组件与提醒清理后联合验收。
- 同一身份已有可信快照也须核对作用域；禁止从被替换的另一身份继承额度。更完整的迟到结果阻断在 T22 验收。

- [ ] 没有额外身份确认，且新身份不会继承被替换身份的额度或成功时间。
