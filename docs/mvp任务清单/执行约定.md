## 2. 任务大小与执行顺序

1. 原 T01 → T56 按原依赖推进；新增 T57 演示添加、T58 外观偏好可在直接前置齐备且用户授权后先实施，不必等到 T56 之后；每次只完成一个文件描述的成果。实际前置以依赖为准；编号较早但未列为依赖的项不自动成为技术前置。等待自然事件证据期间，可以先做前置已齐的独立任务，最终收口不能跳过任何必要验收。
2. 每个任务的实现工作应能在一次对话、一个小提交中完成。任务中实现与相应测试一起交付；不在同一任务里顺手做后续功能。
3. 真机系统调度、真实重置和自然授权到期可能需要经过实际时间。开发者从 T14、T30、T39 起保存去敏观察结果，在 T52–T54 的独立验收任务中核对；不要求对话一直等待，也不把等待另建成开发阶段。
4. 缺少某项真实结果时如实标“待验”，不能以模拟结果替代或写成已完成。自然观察任务具备所需证据后，可在一次会话核验并提交；尚无证据则该项保持待验。
5. 若实际任务超过一个明确成果，应先在本文件夹拆出小任务并更新索引与依赖，然后继续；不擅自扩大产品范围。
6. 发现问题时就地修复与该任务直接相关的问题。验收阶段若发现跨模块缺陷，将缺陷按单一结果拆成修复任务、更新依赖并各自存档，不把“全量验收”变成无限大的修改任务。

新增页面任务同时沿用 T03 的基础样式交付基本浅深外观和可读标签；T37/T47 做完整状态与跨页一致性收口，不能把全部外观实现拖成最后一个大任务。实现超出单次小成果时按第 5 条继续细分。

## 3. 给项目经理的验收方式

- 每份任务先写“本次交付”和“你怎么验收”，开发细节放后面。
- 页面任务：提供可运行版本、入口、操作、预期结果。用户不需要读代码、网络报文或日志。
- 基础能力尚无页面时：开发者运行固定输入的测试，展示易读的“输入／操作 → 实际结果 → 是否通过”表及运行结果。验收不是凭开发者一句“已完成”。后续真机任务仍验证实际体验。
- 难稳定复现的 49/50/51 分、过期、部分失败、迟到响应等，由开发者在隔离测试环境准备，不要求用户制造网络故障或修改代码；任务写明测试构建与真实平台结果的区别。
- 测试数据与真实账户、共享组件数据隔离，不覆盖真实成功快照。用户已明确新增 DEM-01～04 演示添加开关（T57），按该需求实现及清理；不加入故障选择器或其他调试入口。开发者隔离脚手架不冒充产品演示功能，也不替代真实验收。
- 通知逻辑可用虚拟通知中心测试。模拟额度、模拟时间不得向系统发送真实通知。实际锁屏通知必须依据真实账户提供的有效重置时间验收。
- 组件画面刷新、后台执行和系统通知遵守 iOS 调度。开发者记录请求与实际发生的时间，区分“已请求”“调试触发”“自然执行”；不以严格 30 分钟或瞬时换图为通过标准。
- 本轮长按排序、单卡刷新和删除先用演示账户验收，不要求用户用真实账户验证这些操作。后续真实身份去重、重登和真实数据隔离验收仍需至少两个真实 Codex 账户；用户本人完成账户密码/验证码等私密操作。条件未具备时标待验，不把测试账户当真实账户，不为验收开户或购买订阅。

## 4. 每个任务的完成与 Git 存档

Git 仓库：`/Users/iceflying/codex/订阅用量监控/app`。参考项目有自己的仓库，不在其中提交本 App 的改动。

每个任务都执行：

1. 开始前读取项目规则、项目进度、本任务及前置任务的验收/提交记录，检查当前变更，保护其他任务或用户尚未提交的工作。实际开始时同步看板与任务状态为进行中。
2. 完成本任务功能和必要自检。在 `记录/Txx-验收.md` 填写实际结果；同步更新任务文档状态及项目进度中的概况、任务行和交接记录。没有执行的步骤明确标待验，并留下剩余工作和下一次从哪里继续。后续修复和用户验收反馈追加到原记录。
3. 检查差异及新增文件，只暂存本任务实际改动、对应验收记录、状态和项目进度。不得提交授权、密码、真实令牌、签名秘密或不相关文件；不使用盲目的全仓库暂存。
4. 用一次小提交建立存档点，提交信息包含任务编号和结果，例如 `feat(T17): 保存账户排序`；纯验收可用 `test(T51): 记录两尺寸组件真机验收`。若任务只产出验收记录，该记录本身就是可提交成果。
5. 提交后确认产生提交号并检查剩余变更，向用户报告“做了什么、怎么验收、验收结果、待验事项、进度已更新、Git 提交号”。未完成的部分可以保存进行中提交，但不能标任务完成；提交失败必须注明未存档，不保留已完成的表述。

**完成判定：本任务范围内成果存在、所列验收实际通过、结果有记录、任务与项目进度已同步、Git 存档成功。** 用户亲自验收状态另列；开发者不得冒称用户已验收，也不新增每个任务都必须等待用户回复才继续的流程。范围内的小修复、阶段存档、受阻及验收反馈同样更新进度；项目维护单独记录，不计作开发任务完成。未经授权不自动开始下一项。

验收记录随成果提交，不填写该次提交自己的哈希；用任务编号在 Git 历史查找，提交后在交付回复报告实际哈希，避免自引用造成持续修改。用户未明确要求时不推送远端。
