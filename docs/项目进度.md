## 状态怎么读

| 任务状态 | 含义 |
|---|---|
| 未开始 | 还没有执行本任务 |
| 进行中 | 已开始，仍有实现、修复或存档工作未完成 |
| 待验 | 本任务要求的必要验证尚未齐全，不能标完成 |
| 受阻 | 当前无法继续，交接记录必须说明原因及恢复条件 |
| 已完成 | 成果、必要验收、记录、进度更新与 Git 存档均满足要求 |

“必要验收”记录任务要求的实际检查结果；“用户亲验”只根据用户真实反馈填写，二者不互相冒充。用户未亲验不自动阻塞所有后续任务；前置是否完成仍须核对任务记录与实际提交。修复后重新核对受影响结果，旧的通过记录留在历史中。

## 以后怎么启动

在这个项目的新对话中直接发送：

- **开始 T01。** 执行指定任务，前置不足时先说明，不自动跳过。
- **继续上次任务。** 从明确的未完成停点接着做；已完成时先说明，不自动连做下一项。
- **下一项做什么？** 查看依赖并推荐，不立即开发。
- **T01 我验收通过了。** 记录你的真实反馈并存档。
- **T01 有个问题：具体描述。** 处理相应反馈，记录修复及再次验收情况。

无需先建立正式 Issue 或重复粘贴需求。执行者按 [项目规则](../AGENTS.md) 主动读写进度；一次开发指令默认只执行指定范围。
