# iPhone 订阅额度监控需求文档

版本：0.35。建立日期：2026 年 10 月 8 日；最近校订：2026 年 10 月 19 日。

本项目开发一款 iPhone App，让用户连接自己已有的 OpenAI 账户，自动查看 **Codex 订阅剩余额度**、重置时间，并通过桌面小组件和重置提醒减少主动查询的操作。**当前 MVP 做 Codex 与 Cursor 个人订阅（D-77），Cursor 账户另显示 Grok Bot 每周额度（D-80），并做 OpenRouter、DeepSeek 两家的 API 余额（D-82），同平台均支持多个账户。** 用户口述的“GPT 账号”指这里的 OpenAI 账户，不新增 ChatGPT 聊天额度或 OpenAI API 余额功能。

本文规定功能、用户体验和验收；[首版平台登录与额度连接方案](首版平台登录与额度连接方案.md)规定技术研究与接入依据。技术方案已按用户最新确认同步范围、刷新和账户连接规则，保留 13 平台研究证据；其他 12 个平台用于后续扩展，不是 MVP 必须交付的清单，也不表示已完成 iPhone 接入。后续若有差异，以用户最新明确决定为准。

MVP 从订阅额度扩展到 API 余额：连接弹层增加 OpenRouter、DeepSeek 两格，点击后在 App 内粘贴已有 API key，验证查到余额才添加，key 存钥匙串，不开浏览器。OpenRouter 只接受管理密钥（账户余额接口官方要求）。卡片、详情额度卡、小／中号组件只显示“余额”金额（按币种、两位小数），无进度条、百分比、重置时间和重置提醒；DeepSeek 详情另列充值／赠送余额。邮箱位置显示 key 末四位；同一把 key 再添加即原位更新，不同 key 不合并。刷新、失败旧值、简短提示、多账户、排序、组件选账户沿用现有规则；演示各加一个示例；低余额提醒先不做。详见 4.15 与决定 D-82；任务见 T111—T117（两个阶段），尚未实施。

## D-81 百分比显示整数、详情两位小数（2026-10-17，需求0.31）

## 1. 产品目标与核心原则

### 1.1 使用场景

- 打开 App 就查看各账户适用的 Codex／Cursor 剩余额度与重置时间（D-77 起不显示套餐名称），无需先手动刷新。
- 有多个账户时，在同一列表分别查看，并按自己的习惯调整顺序。
- 从主屏幕小组件查看账户的周额度和 5 小时额度，默认首项，可在系统编辑中独立选择账户。
- 在已知的预计重置时间收到提醒，是否开启由用户决定。

### 1.2 能简化就简化

此原则同时约束需求、设计和开发，项目级规则见 [AGENTS.md](../../AGENTS.md)。

- 用户需要结果，不需要理解额度接口、凭据、后台任务或技术错误分类。默认自动完成可以自动完成的事，减少步骤、设置、说明和打断。
- 网络评分不达标时显示简短的“网络不达标，无法更新”；首次获取失败显示“获取失败”，已有可信结果的刷新失败显示“刷新失败”。不展示技术错误码、长原因或排查清单，不要求用户判断故障类别。
- 简化对外提示不改变内部正确性：检查未通过不查询；失败不伪造额度，不改写最后成功时间；失败可重试，不提供重新登录入口或建议。
- 明确功能、信息、流程和状态即可。颜色、间距、精确尺寸、动画时长等不在本轮写死，后续设计和开发可调整。
- 不为假想边界增加设置、复杂选择器或额外页面。未纳入本版的能力留到后续讨论。

### 1.3 名词

“订阅额度”是 Codex 订阅实际提供的额度窗口，不是手机网络流量、历史 token 统计或 API 账单余额。“连接账户”是允许本 App 查询用户已有账户，不是注册本产品账户。“小组件”指 iPhone 主屏幕小组件；“锁屏通知”不等于锁屏小组件。

### 2.2 第一版不包含

- 本产品自己的注册登录、电脑端 App、电脑采集器、电脑日志上传或 Tokens.ci 接入。
- 历史 token、费用、趋势、排行榜、小票分享或打印音效。

### 2.3 保持可扩展性

技术上沿用“一套账户与额度框架，各平台独立接入模块”的方向，复用已有平台查询能力及技术方案中的研究成果。账户识别、排序、快照、刷新、通知、小组件等公共能力不能与 Codex 写成不可分离的一套，数据需保留平台归属和真实窗口含义，方便以后增加平台。

MVP 注册和展示 Codex 与 Cursor（D-77），以及 OpenRouter、DeepSeek API 余额（D-82）。各连接入口先打开统一平台图标选择弹层，目前依次为 Codex、Cursor、OpenRouter、DeepSeek 四个图标，不提前暴露其他平台入口或占位图标；密钥输入只出现在 OpenRouter、DeepSeek 两个余额平台的连接流程中。现有 13 平台仅为研究资料，既不是首版清单，也不是未来可接入平台的上限；后续按用户授权逐步增加。各平台采用自己的实际套餐名称、额度单位、窗口及登录方式，不直接套用 Codex 的两个窗口，也不要求用户逐个确认官方套餐名称。

订阅类型来自该账户的实时查询结果，不维护完整套餐枚举、名称白名单或人工套餐对照表。新增套餐名称只要仍通过已支持的字段返回，即可展示；只有获取协议或字段结构发生变化才可能需要更新接入。通用层保留动态套餐资料、额度适用状态及获取结果，具体可靠来源由各平台接入负责。官网套餐列表可作研究证据，不能代替当前账户资料或成为运行时匹配清单。详见第 4.11 节。

优先手机直接访问平台、无需自建业务后端；新增网络评分服务仍按第 4.8 节使用。具体接口、凭据续期、系统调度和平台兼容性留在技术方案及实现验证中，不要求用户处理。若 Codex 手机接入存在无法满足当前体验的实质限制，再带证据讨论，不自行引入电脑或扩展安装流程。

## 3. 页面与主要流程

第一版主要入口为“额度”和“设置”。

| 页面／入口 | 用户能做什么 |
|---|---|
| 无账户页／连接入口 | 打开统一平台选择底部弹层，显示 Codex、Cursor 图标；点图标后才开始连接 |
| 平台登录 | 在系统默认浏览器完成 OpenAI 或 Cursor 必要的登录／确认，返回 App 后自动继续（Cursor 备选方式见 CUR-02） |
| 额度看板 | 查看所有账户独立卡片，常显平台名（不显示套餐），自动更新或手动刷新，展开详细更新时间，调整账户顺序 |
| 账户操作 | 对指定账户刷新或断开连接 |
| 设置 | 卡片样式选择、重置提醒、手动明暗、最底部演示开关，以及小组件教程、帮助、隐私和开源许可；无账户区域 |
| 小组件教程 | 学习添加小号／中号组件；组件默认显示首账户，可长按编辑选择显示账户 |
| 系统小组件 | 查看当前组件账户的平台名及适用额度，点击进入该账户内容 |

主要流程：

1. 点击连接 → 平台图标选择弹层 → 点击 Codex 图标 → 新增前检查网络 → 通过后在默认浏览器完成授权 → 回 App 自动继续 → 验证身份和凭据 → 首次查询前检查 → 取得平台实际套餐资料 → 判断额度适用性并显示真实结果。套餐与额度可来自同一次可靠响应，不强制拆成两次请求。已确认无本期适用额度与获取失败分别处理，见 SUB-03～05；失败保留有效账户，不伪装成查询成功。
2. 添加不同账户 → 追加到列表末尾；用户可移动顺序。同邮箱重复添加按 ACC-10 处理，独立重登及换号替换按 D-59 取消。
3. 打开／回到 App → 自动刷新现有账户，与后台 30 分钟周期独立；不要求先点刷新，也不因后台刚更新过而跳过本次前台更新。
4. 后台获得执行机会 → 检查网络 → 自动查询 → 更新成功快照并请求小组件更新；失败保留旧数据，不弹出打断用户的窗口。
5. 添加小组件 → 默认显示列表首个账户；长按→编辑小组件→显示账户，可为每个组件独立选择。默认选择随列表首项，手动选定后随该账户更新；选定账户移除后安全回首项，无账户显示添加入口。
6. 开启提醒 → 申请系统通知权限 → 按有效预计重置时间安排提醒；点击通知进入对应账户并自动更新。

| ACC-13 | 首次获取失败可继续恢复 | 已验证绑定后首次检查或资料／额度查询失败仍保留账户及已取得的套餐；网络低分按 NET，其余首次失败显示“获取失败”，允许重试；不显示假值或假成功时间。已确认无适用额度走 SUB-03，不进入失败占位 |

去重依据是同平台可靠邮箱；内部仍保留新登录的服务端账户和作用域标识，以保证取到的是本次选择的套餐和额度，不能把两个工作区的数据相加或串用。无法可靠识别身份时不能误删其他记录。有效绑定、真实套餐查询与真实额度查询分别验收；确认无本期适用额度可以完成该账户资料展示，但不能代替有额度账户的真实额度验收。

| 编号 | 要求 | 验收条件 |

| QTA-01 | 每账户独立卡片 | 不合并不同账户额度；按所选样式显示“平台 · 实际套餐”及适用真实窗口、剩余值和预计重置；新样式不补邮箱行，原样式App保留原排布；Codex点击卡片打开D-66专用详情面板，替代卡片内展开 |

### 4.11 动态订阅资料与额度适用性

2026-10-10 用户以 Codex 账户为例确认：名称来自平台账户资料，不来自用户口述、不翻译成自定会员文案，也不先维护套餐清单再逐一匹配。通用规则适用于以后逐步接入的任意平台，当前只实施 Codex。

| 编号 | 要求 | 验收条件 |
|---|---|---|
| SUB-01 | 从当前账户取得实际套餐 | 使用该账户的有效授权查询可靠套餐资料，绑定账户／产品／作用域；保存平台提供的实际名称或标识。优先实际显示名称，只有标识时保留标识，不编造更具体名称；不依赖用户确认、官网价格表或预设名称白名单 |
| SUB-02 | 常显平台与原套餐名称 | 使用居中的间隔号 U+00B7，格式为“平台 · 套餐”；例如平台返回 Free、Plus 时分别显示“Codex · Free”“Codex · Plus”。不改成“免费版”或追加“会员”；保留平台名称含义及大小写。未知的新名称经同样字段返回时也能展示；名称缺失不补成 Free |
| SUB-03 | 套餐取得与额度适用分别判断 | 先取得套餐资料，再按该平台真实返回及可靠语义判断适用额度；可共用同一响应。Codex 已确认 Free 且无本期适用周／5 小时额度时，只显示套餐和身份，隐藏额度、重置与额度成功时间，不显示“尚未获取额度”或因此报失败。此规则不声称平台完全没有使用量，也不将所有平台的免费套餐等同无额度 |
| SUB-04 | 缺失或失败不能冒充无额度 | 套餐资料、适用性或应有额度未获取成功，按 QTA-08 提示；保留已取得的可信套餐，首次无套餐则仅显示平台名。不能以空列表、缺字段或不认识名称判定免费、无额度、零或不限量；真实 0 仍是有效额度结果 |
| SUB-05 | 资料成功与额度成功独立 | 套餐资料取得可以保存并展示，即使后续额度失败；两者观测结果和成功时间分别记录。仅套餐成功不能使应有额度查询整体变成功。可靠确认无适用额度可以正常结束本次账户更新，但不生成虚构额度快照 |
| SUB-06 | 现有刷新机制更新套餐 | 登录后、打开／回 App、手动及系统允许的后台更新均重新取得实际套餐，不能因曾为 Free 就永久跳过更新。实时指本次查询所得，不承诺持续连接或后台准点。确认套餐变化时更新名称，旧套餐额度不得挂到新套餐下，重新取得适用额度并撤销不再适用的提醒；请求失败本身不证明套餐变化 |
| SUB-07 | 公共展示与平台差异分离 | 公共层使用动态套餐资料和明确的额度适用／获取结果；各平台负责可靠取数和真实单位、周期及作用域。App、组件、提醒使用一致结果。新增套餐名称不要求发版，获取协议或字段结构改变可能需要适配；不新增套餐选择器、用户命名或配置步骤 |

已确认的 Codex 显示例子（名称以可靠返回为准，以下不是完整枚举）：

| 查询结果 | 显示结果 |
|---|---|
| 套餐名称 Free，成功确认无本期适用周／5 小时额度 | Codex · Free，保留身份；不显示额度区域或失败占位 |
| 套餐名称 Plus，成功取得周／5 小时额度 | Codex · Plus，显示实际剩余及真实时间 |
| 平台返回此前未列出的新套餐名称，响应结构仍受支持 | 直接显示 Codex · 平台返回名称；照真实额度信息处理，不因名称新而失败 |
| 已取得套餐名称，应获取的额度失败 | 保留套餐；首次显示“获取失败”，已有可信结果时保留原数据与时间并显示“刷新失败” |
| 首次套餐资料获取失败 | 仅显示 Codex 和“获取失败”，保留有效绑定；不猜套餐 |

Codex 本期仍不展示 30 天窗口、credits 或 API 余额。识别新套餐名称不自动扩大额度指标范围；无法确认适用性必须保留未知并提示获取失败，不能将所有未支持窗口都自动归为正常无额度。网络前置检查沿用 NET，不以资料查询或免费账户为理由绕过。

| BAL-03 | OpenRouter 管理密钥 | 只接受管理密钥（Management key），输入页简要说明并给出创建路径：openrouter.ai 左上角两条杠菜单 → Account（账户）分组 → Management Keys → 创建（不是顶部 Settings）；普通 key 查询账户余额被拒时不添加账户，在连接弹层简短提示并可重新输入，不罗列技术原因 |
| BAL-04 | 凭据保存 | 验证成功后 key 只存本机钥匙串，不进日志、截图或仓库；删除账户只删本 App 的 key 与缓存，不撤销平台上的 key |
| BAL-05 | 金额显示 | 账户卡、详情额度卡、小号与中号组件以“余额”金额为主体，按币种显示符号（OpenRouter 美元；DeepSeek 按返回币种，多币种分行），两位小数；不画进度条、不显示百分比与重置时间；13 款样式与浅深适用 |
| BAL-06 | 详情 | DeepSeek 详情列表另列“充值余额”“赠送余额”；OpenRouter 不加额外行；更新时间等通用行照常 |
| BAL-07 | 账户区分与去重 | 原邮箱位置显示 key 末四位（如“sk-…a1b2”），无命名步骤；同平台同一把 key 再添加即更新原账户、位置不变；不同 key 各成账户，不合并、不相加余额 |
| BAL-08 | 真实金额 | 金额按十进制精确解析；余额为 0 如实显示 ¥0.00／$0.00 且不引导充值；缺字段不当 0；DeepSeek 余额不足以调用 API 不算失败 |
| BAL-09 | 刷新与失败 | 刷新时机、网络检查、首次“获取失败”、已有结果“刷新失败”、保留旧值与原成功时间与订阅平台一致；key 失效不提供更换入口，按 D-59 通过添加新 key 再删除旧账户 |
| BAL-10 | 无重置提醒 | 余额没有重置周期，不安排重置提醒；重置提醒总开关不影响余额账户 |
| BAL-11 | 其余一致 | 多账户、排序、D-64 组件选账户、删除、演示（各一个模拟金额示例账户）与现有规则相同 |

## 5. 数据与隐私

仅保存查询需要的本 App 授权、账户身份与顺序、最近成功快照及用户设置。凭据安全保存在本机，不进入普通日志、示例截图或仓库；小组件仅取得必要信息，不额外收集用户资料。

账户资料保存平台实际套餐名称／标识、可靠来源及其成功观测时间；额度另存适用性、获取状态和最后成功时间，不靠可空数值混同“不适用”与“失败”。每份额度至少区分平台、实际账户／作用域、所属订阅、窗口、数值及单位、限额和重置是否已知。内部准确性不能因为简化用户提示而丢失。新登录、套餐变化、断开或替换后的迟到请求不能覆盖新状态、串入另一账户或恢复已删除数据。

不采集电脑聊天、代码或会话日志；不上传 Tokens.ci。断开只移除本 App 的连接与数据，不取消订阅、退出全部浏览器或破坏电脑已有登录。重复登录替换的是本 App 旧记录，不操作平台上的账户或订阅。

## 6. MVP 验收清单

本清单用于真实产品验收，不表示本次文档修订已执行功能测试。历史 R4 仅证明当时的模拟范围，T12 原证据也不能替代 0.9 新行为验证。

- [ ] 仅展示 Codex 入口；无需本产品注册、API key、扩展或电脑辅助，默认浏览器可完成已验证的手机连接流程，返回 App 自动继续。
- [ ] 真实账户、真实周／5 小时窗口、剩余值和重置时间与平台一致；没有有效返回不伪造；重置到点不自动改满。
- [ ] 至少两个 Codex 账户同时显示且数据独立；新账户追加末尾，额度页长按卡片拖动后重启保持顺序，无把手；设置没有账户管理或连接入口。
- [ ] 卡片菜单仅刷新额度／删除账户，作用于点选账户。演示开启可重复新增及模拟刷新，关闭清除全部演示账户且真实数据不变。
- [ ] 首次按系统显示；手动浅深选择立即生效，重开及系统切换不覆盖用户选择。
- [ ] 同平台同邮箱重复登录只保留最新连接，不报重复；不同邮箱添加为独立账户；取消／失败的新登录不先删除旧记录，旧请求不覆盖新登录。
- [ ] 套餐来自实际账户资料，标题使用“Codex · 平台返回套餐”；Free 不翻译成“免费版”，未预设的新名称可以直接展示，缺失名称不默认 Free。
- [ ] 真实 Free 账户成功确认无本期适用额度时只显示套餐及身份，不出现额度、重置、虚构成功时间或失败占位；不以此代替有额度账户的真实查询验收。
- [ ] 已验证绑定首次获取失败显示“获取失败”并可恢复；套餐取得与额度取得分别保存，前者不掩盖后者失败；另一身份不继承旧额度或通知。
- [ ] 套餐升级、降级或名称变化在正常刷新后采用真实结果；失效的旧额度不挂在新套餐下，提醒及组件同步；获取失败不擅自推断套餐变化。
- [ ] 打开及回到 App 自动刷新，不等待 30 分钟周期，不因缓存新而跳过；已有同范围进行中请求可复用。
- [ ] 后台按 30 分钟目标请求更新，遵守系统执行机会；成功结果用于 App 和组件，失败保留旧值，无强制后台弹窗或自动打开登录页。
- [ ] 全部／单账户手动刷新及重试范围正确；部分账户成功时写入其新数据，失败账户保留旧值，提示仍简短。
- [ ] 所有新增和查询前评分有效且 > 50 才继续；49／50 阻止，51 可继续，无法取得评分不放行且不伪造分数。
- [ ] 用户只看到必要的网络不达标、首次“获取失败”或后续“刷新失败”及恢复操作，不出现技术错误码、评分解释或长排错内容。
- [ ] 成功立即隐藏顶部条；失败常驻可“×”关闭；列表上移无留白；已关闭的同次提示不因页面切换重现，原数据和时间保留。
- [ ] 小号和中号均可实际添加；所有组件显示当前首账户的实际套餐与适用额度。当前账户确认无本期适用额度时只显示套餐及身份，不跳过它，也不显示假时间；没有独立选账户设置。
- [ ] 排序、移除首项及重复添加更新连接后准备正确组件数据并请求系统更新；无账户显示“未连接账号，无数据”，首项无额度不跳到下一账户。
- [ ] 点击组件进入其展示账户；旧画面失效目标和历史通知不会恢复删除数据或被当作另一身份的通知。
- [ ] 全局通知开关持久保存并适用于新增账户；权限拒绝不反复打断；有效窗口按预计时间提醒，重复刷新不重复通知，关闭／移除／替换时取消相应待发提醒。
- [ ] 首页与设置均可进入两步添加教程，动画和静态步骤可理解可退出，不含编辑选择账户步骤，不暗示自动添加。
- [ ] 卡片样式13选项、点选自动保存／重开保持；所有账户、详情额度卡与全部小／中号实例跟随，实例账户保持。实际原生验收覆盖明暗、窗口、0／100／小数、异常旧值、大字号与减少动态，强调剩余／灰色已用；组件无邮箱或时间，水印静态。
- [ ] Cursor 账户的“Grok Bot”行与 Grok Bot App 显示一致；没有 Grok Bot 额度的账户不显示该行；失败保留旧值；每周重置提醒正确（D-80）。
- [ ] 隐私、帮助、开源列表及许可详情可查看和返回；凭据、数据删除和账户隔离符合第 5 节。
- [ ] 技术层公共账户／额度能力与 Codex 接入分离，具备后续增加平台的结构，不要求实现其他平台才能通过 MVP 验收。
