## 本次交付与范围

用Swift原生请求实现两家余额查询（借鉴CodexBar已核实的字段与校验，不引入其JS插件）：

- OpenRouter：`GET /api/v1/credits`，固定发往`https://openrouter.ai`；两字段须为有限数字，余额＝max(0, total_credits − total_usage)，美元。
- DeepSeek：`GET /user/balance`；金额字符串按Decimal解析，按`currency`分开，取总余额、充值、赠送；`is_available=false`不算失败。
- 结果分类只供内部：成功／key被拒（401、403）／网络或其他失败；对外沿用“获取失败”“刷新失败”，不展示技术原因。
- 接入现有刷新：新增前与每次查询前网络检查，打开／回App、下拉全部、单卡刷新、后台与组件自主更新走同一查询；失败不覆盖旧值。

## 必要检查

- 解析单元测试（用T111去敏样本）：正常、0余额、小数精度、多币种、缺字段、非数字、非200、401／403、超时；OpenRouter普通key 403判为被拒。
- 刷新路径测试：余额账户与Codex／Cursor账户混排时各自独立，单账户失败不影响其他账户。
- 单元测试全集0失败。
