## 本次改动

- 新增 `Sources/Providers/APIBalance/APIBalanceService.swift`（App 与组件两个目标）：
  - `APIBalanceParser`：OpenRouter `data.total_credits`／`total_usage` 必须是 JSON 数字（字符串、布尔、null、缺失都失败），余额＝max(0, 总充值−总已用)，美元；DeepSeek `balance_infos[]` 按币种取 `total_balance`（必需）、`topped_up_balance`、`granted_balance`（缺失为未知），金额字符串按十进制解析，必须有 `is_available`（为 false 仍算成功），空数组、重复或非法币种失败。
  - `APIBalanceClient`：只请求固定地址 `https://openrouter.ai/api/v1/credits`、`https://api.deepseek.com/user/balance`，Bearer 头，20 秒超时，不跟随重定向（沿用现有传输），返回地址必须一致；401／403＝被拒，其他非200、HTML、超大、空响应、网络错误＝失败。分类只供内部，界面仍只显示“获取失败／刷新失败”。
  - `APIBalanceService`：钥匙串取 key→核对指纹与账户一致→查询前网络检查→查询→确认 key 在请求期间未被替换→`saveBalance`；任何失败只写失败标记，保留旧余额与原成功时间（网络不达标单独标记）。
- `CoordinatedQuotaUpdater`：余额账户走新服务（同一租约、30 分钟间隔与绑定核对）；自动更新的“30 分钟内已成功则跳过”也看余额的成功时间；App 与组件的 `live()` 都接入。打开／回 App、下拉全部、单卡刷新、后台、组件自主更新都经过这一入口。
