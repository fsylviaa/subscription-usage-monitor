## 实现

账户文件与 Keychain 使用同一持久化执行器。登录提交、续期提交和额度写入按当前身份、作用域、账户版本与删除状态检查；续期的版本检查与凭据条件替换中间不挂起。即使旧凭据因清理失败仍物理存在，旧续期也不能写回。登录取消标记与 Task 取消均在正式绑定提交前检查。

删除先落盘，随后清理本机连接，不再等待不配合取消的旧查询结束。页面忽略已删除或已更新连接的旧错误结果。没有新增设置、提示或正式测试页面，没有改 Figma 或实现后续任务。

## 具名隔离结果

使用测试账户 A、C 及待添加 B；初始剩余 40%、成功时间 t；新连接剩余 80%、成功时间 t+200；旧结果为剩余 1%、t+300。它们全部是固定样例，不是真实余额。

| 操作／输入 | 预期 | 实际结果 | 结论 |
|---|---|---|---|
| 挂起添加 B 成功结果，取消事务，再释放旧登录 | 无 B 绑定，A／C 不变 | 无 B；A/C 完整保持，取消事务不恢复 | 通过（隔离） |
| 挂起 A 旧查询，完成 A 新连接与新查询，再释放旧额度 | 保持最新连接、80%及 t+200；C 不变 | A 仍在原位；保留新授权、80%和 t+200，迟到的 1%／t+300 被拒绝 | 通过（隔离） |
| A 查询中删除 A，再释放旧查询 | A 不复活，旧授权与快照不恢复 | A 不存在，旧授权读回为空，C 保持 | 通过（隔离） |
| 续期响应或核验挂起时标记删除，保留旧授权模拟清理中断，再释放 | 两阶段均不能写回；重开完成清理，仅 C 留存 | 响应提交与核验提交均拒绝；旧包未改，重开清理后只有 C | 通过（隔离） |
| 续期响应或核验挂起时完成新连接，保留待清理旧授权，再释放 | 两阶段拒写；新授权完整保持，后续查询实际使用新授权 | 旧包与新包均未被旧续期改写；后续请求携带最新授权 | 通过（隔离） |
| 每个场景后重建文件与 Keychain reader | 结果持久保存，C 身份、顺序、额度、成功时间及授权不变 | 文件重读完全一致；C 的完整记录及授权逐项一致 | 通过（隔离） |
| 取消刷新后释放成功／页面删除时查询仍挂起 | 原值原时间保持；删除及时完成、迟到结果不带回账户或错误 | 取消刷新保持原值原时间；页面删除先完成，释放旧响应后不复活 | 通过（隔离） |

## 本人怎么验收

本任务核心是上述延迟结果表，由开发者用隔离场景运行，不要求本人制造慢网或重复真实登录。手机安装最终版本后：

1. 阅读上表，确认取消不新增、删除不恢复、旧结果不覆盖新连接这三类结果符合预期。
2. 设置开启演示模式，回额度页添加两个演示账户 A、C。对 A 点菜单 → 删除账户 → 取消，两张卡应仍在。
3. 再删除演示 A，彻底关闭并重开 App：A 不应回来，演示 C 的位置和数值保持。不要删除真实账户。
4. 设置关闭演示模式，确认样例清空、原真实账户保持。

本人无需核对真实五小时余额，也不需要操作 Xcode。上述页面步骤属于体验复验，不能替代开发者的具名迟到场景；亲验结果收到后另记。
