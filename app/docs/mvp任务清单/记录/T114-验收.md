## 本次改动

- 平台：`ConnectionPlatform` 增加 OpenRouter、DeepSeek（排在 Codex、Cursor 之后），格内平台名同 D-78；新增资源 `DesignOpenRouter`／`DesignDeepSeek`（Lobe Icons 1.95.1 官方标志，处理同 T102，来源与 SHA-256 记入 `Resources/README.md`）；设置“开源许可→Lobe Icons”的采用内容改为四个平台标志。
- 流程（`CodexConnectionFlow`）：点格→网络检查（未达标“网络不达标，无法连接”，可重试）→输入页 `keyEntry`；点“连接”→再做一次查询前网络检查→用该 key 在内存中查一次余额→成功才 `save(balance:)`（同 key 原位更新，否则追加末尾）并关闭弹层；被拒／失败留在输入页，简短提示后可修改重试：OpenRouter 被拒“key 无效或不是 Management key”，DeepSeek 被拒“key 无效，请检查后重试”，其他“连接失败，请重试”，格式不对“请粘贴完整的 key”。取消立即作废本次尝试，迟到的结果不保存。
- 输入页（`APIKeyEntryView`）：平台标志、说明、安全输入框（`SecureField`，关闭自动大写／纠错，`privacySensitive`）、系统“粘贴”按钮（不触发读取剪贴板授权弹窗）、“连接”按钮。OpenRouter 说明两句：“请粘贴 OpenRouter 的 Management key（管理密钥），普通 API key 查不到账户余额。创建路径：openrouter.ai 左上角两条杠菜单 → Account → Management Keys（不是顶部 Settings）。”DeepSeek：“请粘贴你在 DeepSeek 开放平台已有的 API key，App 只用它查询余额。”key 只在该页的状态里，页面关闭即清空；不打开浏览器，无创建 key 或充值步骤。
