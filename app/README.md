### 在 Xcode 中运行

1. 打开本目录的 `SubscriptionUsage.xcodeproj`（可以双击，或在终端运行 `open SubscriptionUsage.xcodeproj`）。

5. 关闭工程窗口后重新打开同一个工程，再按 **⌘R**；运行方案与必须配置均已保存到仓库。

如果另一台 Mac 没有对应模拟器，在 Xcode 的运行设备列表中选择已安装的 iPhone 模拟器（iOS 17 或以上），或在 **Xcode → Settings → Components** 安装所需 iOS 模拟器运行环境。不同 Xcode 版本的界面可能略有区别，参见 [Apple 模拟器组件说明](https://developer.apple.com/documentation/xcode/downloading-and-installing-additional-xcode-components)。切换 Xcode 的命令行工具方式见 [Apple 工具配置说明](https://developer.apple.com/documentation/xcode/configuring-command-line-tools-settings)；本项目命令用 `DEVELOPER_DIR` 只影响当前终端会话。

### 开发者检查命令

在 `app` 目录执行。若 Xcode 安装位置不同，只需将第一行改为实际位置；其他模拟器可按列表中的名称与系统版本替换 `-destination`。

```sh
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
xcodebuild -version
xcodebuild -list -project SubscriptionUsage.xcodeproj
xcrun simctl list devices available

xcodebuild -project SubscriptionUsage.xcodeproj \
  -scheme SubscriptionUsage \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=26.5' \
  -derivedDataPath build/DerivedData build

xcodebuild -project SubscriptionUsage.xcodeproj \
  -scheme SubscriptionUsage \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=26.5' \
  -derivedDataPath build/DerivedData \
  -parallel-testing-enabled NO test
```

`build` 只验证编译；`test` 会启动模拟器、运行单元与 UI 测试，界面测试会终止并重新启动 App。两者不查询真实账户、不读电脑授权。测试后可再次按 ⌘R 查看页面。

复查不依赖已有构建缓存时，将 `-derivedDataPath` 改成一个全新目录，如 `build/FreshDerivedData`，重新构建并按上面步骤运行。`build/`、构建结果、Xcode 个人状态均不提交。后续测试样例的隔离规则见 [Tests/README.md](Tests/README.md)；实际执行记录见 [T01 验收](docs/mvp任务清单/记录/T01-验收.md)。

### T04 做了什么、怎么验收

**这一步让 App 能记住账户和排列顺序。** 例如以后添加两个账户 A、B，App 要记住它们；把 B 移到前面，要记住新顺序；修改 A，不能弄乱 B。

现在还没接上登录和账户列表，所以打开 App **不会出现新页面，也还不能添加账户**。这一项由开发者用两个虚构账户运行检查，你查看[T04 验收结果](docs/mvp任务清单/记录/T04-验收.md)即可：

| 我们检查什么 | 应该得到的结果 |
|---|---|
| 保存 A、B，再重新读取 | 两个都在，仍是 A、B |
| 改成 B、A，再重新读取 | 记住 B 在前的新顺序 |
| 只改 A | B 不变 |
| 还没查到额度 | 不凭空显示额度数字或更新时间 |

**你不需要操作 Xcode 才能验收这一步。** 真正的手机操作验收会在登录、账户列表和排序功能接好后进行，届时再添加自己的账户、调整顺序、关掉重开。

如果想亲自看自动检查运行（可选）：

1. 在 Xcode 顶部设备位置选 **iPhone 17 Pro 模拟器**，按 **⌘U**。
2. 等它自动结束，看到 **Test Succeeded**（测试通过）就是成功；不用在 App 里寻找测试按钮。
3. 若选连接的实体 iPhone，则先解锁并保持连接。App 和两个测试程序现已共用本机签名配置；仍需此 Mac 已按 T02 配好签名。

开发者只运行 T04 存储检查时使用以下命令；它使用临时测试数据，不访问真实账户、钥匙串或网络：


### T05 做了什么、怎么验收

本次没有新页面，也还不能登录。由开发者使用虚构授权运行检查，你查看 [T05 验收结果](docs/mvp任务清单/记录/T05-验收.md)中的实际结果即可，无需自行排查 Xcode。后续登录与账户管理接好后，再验证真实手机操作。

### T06 做了什么、怎么验收

**这一步让 App 在连接或查询前，判断指定网站的网络评分是否达标。** 使用 [Net.Coffee 的 Claude AI 信任评分](https://ip.net.coffee/claude/)，只有有效分数大于 50 才继续；49、50、无法取得评分和取消都不继续。不是普通连通性测试。

本次仍没有新增操作页面。开发者先运行检查，再提供 [T06 验收结果](docs/mvp任务清单/记录/T06-验收.md)。你只需对照其中的真实取分摘要、固定结果表和 Xcode 通过报告，无需更换网络或制造故障。连接按钮从 T07 接入。

2. 如尚未开启，在 iPhone 的 **设置 → 隐私与安全性 → 开发者模式** 开启，按提示重启，再确认开启并解锁。参见 [Apple 开发者模式说明](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)。
3. 在 **Xcode → Settings → Apple Accounts** 登录自己的 Apple 账户。用户本人输入密码、验证码和处理账户协议；不向聊天或仓库提供这些信息。
4. 打开工程，选择 App target **SubscriptionUsage → Signing & Capabilities**，保持 **Automatically manage signing** 开启，使用自己的开发团队。当前协作者测试 Bundle Identifier 为 `com.pbpuw6l86s.SubscriptionUsage`，Widget 为 `com.pbpuw6l86s.SubscriptionUsage.Widget`；个人 Team 配置保存在本机忽略文件中。
5. 顶部运行设备选择 **iOS Device** 下的实体 **iPhone**，按 **⌘R**。等待 Xcode 完成设备准备、构建和安装；如系统要求解锁，先解锁手机；若提示开发者证书未受信任，在手机 **设置 → 通用 → VPN 与设备管理** 中信任自己的开发者账户，然后回 Xcode 再运行。参见 [Apple 真机运行说明](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices)。
6. 手机出现两行标题后，回到主屏幕，点击“Token 仪表盘”图标再打开一次。
7. 在 Xcode 点击停止调试，再从手机桌面打开一次；能看到相同页面才完成本任务最后一项验收。

这是 Xcode 的开发安装，受实际开发签名有效期限制，不代表永久安装或分发版本。T02 只验证 App 本体；未添加小组件、App Group 或发布配置。若尚无可用团队，先完成账户登录；不通过撤销现有证书来尝试修复。

开发者保存签名配置：将团队 ID 写入被忽略的 `Config/Signing.local.xcconfig`（`DEVELOPMENT_TEAM = 自己的团队ID`），由 `Config/Signing.xcconfig` 供 App 和两个测试程序的 Debug/Release 配置共同读取。若在 Xcode 选团队时写回了工程，提交前移除工程内覆盖本机文件的团队字段；实际团队、账户资料和签名秘密不入 Git。缺少本机文件仍可运行模拟器，真机需重新配置自己的团队。

## 研究结论

参考产品已识别为 Nowdex。它的订阅额度查询与历史 token 统计是两条不同链路：前者由设备向平台查询；后者通过电脑 Tokens 采集器上传汇总，再由手机读取 Tokens.ci。不能把“不自建业务后端”理解为“不使用任何云端服务器”。

详细证据、开源项目用途、数据流和实施方案见 [Nowdex 实现研究](docs/nowdex-research-2026-10-08.md)。

## 初步可行性判断

无自建后端是待验证的方向，而非已确定的结论。没有本产品的注册登录系统，仍然需要安全处理第三方账户授权、凭据过期和重新绑定。

CodexBar 的电脑端功能部分依赖浏览器登录状态、命令行工具和本地文件。iPhone App 不能直接照搬这些读取方式。首版 Codex 需要验证能否在目标设备完成授权，以及能否直接取得真实订阅余量。普通 API 余额与订阅额度也需要分开判断。

## 历史登录与额度阶段说明（T07～T14）

以下按当时版本保留说明；不作为当前功能缺失或待验状态的判断，当前结论统一查看项目进度及各任务最新记录。

### T07 用户验收（历史版本）

以下保留 T07 的验收范围；当前 T08 版本按下方入口操作，官网完成后会继续核验并保存账户。T07 当时手机已安装对应版本。先打开“订阅用量”，不需要运行测试或看日志：

1. 在“额度”点“连接账号”，在平台弹窗点 Codex 图标，等待自动检查。网络合格后应直接看到一次性代码，不用再次确认通过。
2. 点“复制代码”，应变成“已复制”；点“打开官网”，应使用手机当前默认浏览器到达 OpenAI 官方登录／设备确认页。官网如要求登录，使用你已有的账户；需要代码时可粘贴，内容应与 App 一致。
3. 有效期内返回 App，应仍保留本次代码；点“取消”，回到原来的页面。也可从顶部连接图标和“设置 → 连接账号”分别试一次，取消后应回到各自来源。
4. 本步到打开官网为止；返回后仍未添加账户、仍无额度是 T07 当时预期。领取登录结果和保存账户属于 T08。

如显示“网络不达标，无法连接”，表示该次网络未通过规定检查；不会申请代码。其他失败仅显示“登录未完成，请重试”。开发者已负责验证 50／51／未知、申请失败与慢检查取消，你不需要制造网络故障。详细证据见 [T07 验收](docs/mvp任务清单/记录/T07-验收.md)。

### T08 的验收入口

本步接通官网确认后的身份核验与首次账户保存。开发者自验和用户亲验分别记录在 [T08 验收](docs/mvp任务清单/记录/T08-验收.md)。测试构建没有新增演示页面，普通启动不会使用虚构身份；真实登录需用户本人完成官网的私密操作。

### T09 的验收入口

本步完善取消、失败、到期和重试。开发者先运行真机功能和隔离页面验收；难复现的拒绝、交换失败、到期与迟到响应不要求用户制造。实际结果及剩余真实步骤见 [T09 验收](docs/mvp任务清单/记录/T09-验收.md)。

当前已有账户时正式连接入口仍禁用，不能为验收清除原账户或提前实现重登。开发者准备独立验收环境后，用户只需按记录检查取消和再次正常官网确认；正式存储保持原样。

### T10 返回后继续登录

有效登录在浏览器往返、后台返回或关闭重开后自动继续原代码及原阶段；无需点击“我已登录”。已无法安全恢复或到期时简短提示重试，取消后不会恢复旧流程。真实官网确认后应仅保存一条账户，T10 当时显示“尚未获取额度”；后续 T12 接入真实查询。开发者自验与本人操作步骤见 [T10 验收](docs/mvp任务清单/记录/T10-验收.md)，任务状态以[项目进度](docs/项目进度.md)为准。


### T11 正确解释周和 5 小时额度

这一步完成额度含义与转换：周已用 30% 得到剩余 70%，5 小时已用 80% 得到剩余 20%；真实零值、缺失、不限量和重置时间分开处理。T11 当时只做纯解释；正式查询现由 T12 接入。

你无需重新登录、修改代码或制造异常。开发者先运行固定输入测试，再提供 [T11 验收结果](docs/mvp任务清单/记录/T11-验收.md)：逐行核对正常转换、0／100、缺失不补数、窗口交换不混淆、到点不改满这五项即可。结果表与 Xcode 专项测试报告都可查看；亲验反馈单独记录。

### T12 查询并保存真实额度

登录完成后自动检查网络并查询本次账户；已有未获取额度或缺套餐资料的已验证账户在启动后自动补齐，无需为了升级重复登录。套餐来自平台实际 `plan_type`，不预设名称名单；确认 Free 无本期适用额度时收起额度区域，不显示“尚未获取额度”或因此报失败。有适用额度时显示周／5 小时剩余、各自预计重置及“更新于”。套餐可在额度失败时单独保存；同套餐失败保留原额度与时间，确认换套餐则清除旧套餐额度。

当前真实账户返回小写 `free`，已在手机核验“Codex · free”、无额度区域／失败提示及关闭重开。你只需打开“订阅用量”核对这两点，再完全关闭后重开确认一致；不需要重新登录。有额度账户的真实核对仍单列待验。

当前接入首次查询、首次失败重试和最小可读结果；常规手动刷新、持续自动刷新、详情和完整卡片仍按后续任务完成。开发者自验结果、同次真实核对摘要和用户验收步骤见 [T12 验收](docs/mvp任务清单/记录/T12-验收.md)。

### T13 首次失败后重试

已验证账户首次获取失败时保留身份与已知套餐，点账户下方“重试”即可重新检查网络并查询原账户。查询中不重复发起；成功后清除失败及重试入口。确认 Free 无本期适用额度时正常收起额度区域，不显示假百分比或额度时间。正常数据的一般手动刷新仍归 T25/T26。

本次用户允许在 T12 真实有额度查询仍待验时先实施 T13；可执行自验及当前 Free 的真实恢复查询已通过，有真实周／5 小时额度的恢复结果继续待验。开发者已在电脑的 iPhone 模拟器准备独立演练账户，用户可先核对“获取失败”仍保留套餐和身份，再点“重试”，确认同一账户出现周剩余 70%、5 小时剩余 20%，且错误与重试按钮消失。这些数值是隔离样例，不是真实账户额度。完整结果和操作说明见 [T13 验收](docs/mvp任务清单/记录/T13-验收.md)。

### T14 自动续期登录授权

查询时自动处理临近到期的手机授权，适用的首次认证失败最多续期后重查一次。失败保留原账户、可信额度及原成功时间；每次实际查询仍通过网络评分检查，不新增页面或设置。实现、开发者验收与用户验收均已通过，详见 [T14 验收与用户反馈](docs/mvp任务清单/记录/T14-验收.md)。真实现有 Free 授权查询通过，续期成功／失败由隔离测试验证；T54 的两次自然到期和 T12／T13 的真实周／5 小时额度仍待验。日常成功账户刷新、前台触发及后台调度按后续任务接入。
