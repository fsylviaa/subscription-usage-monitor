# 订阅用量监控 App

基于开源项目 [CodexBar](https://github.com/steipete/CodexBar) 的能力和实现经验，开发一款查看订阅剩余额度的 App。首版只做 Codex，支持多个 Codex 账户；技术保留后续增加平台的能力。

首次记录：2026 年 10 月 7 日。最近更新：2026 年 10 月 10 日。

当前依据为需求 **0.8** 及产品决定 D-40～D-50；D-50 为本次技术文档同步校订。与旧文档、历史决定或 Figma 原型不一致时，以最新确认规则为准。本轮同步修订需求、技术连接方案和关联文档，不代表 Figma、App、后台调度或真实平台连接已经实现或验收。

## 已明确的目标

- 参考和复用 CodexBar，具体复用范围通过后续技术验证确定。
- 第一版仅开发 iPhone App，暂不开发电脑端 App。
- 第一版 MVP 只接入 Codex；用户所说的 GPT 账号指 OpenAI 账户的 Codex 订阅额度，不增加 ChatGPT 聊天额度功能。技术结构保留其他平台扩展能力，原型中的三平台图标不限定长期平台范围。
- 核心功能为 Codex 多账户的订阅剩余额度、重置时间、桌面小组件、额度重置通知和小组件添加教程；产品内体验演示已取消。
- App 与小组件固定显示剩余，不提供“额度显示”设置；进度条左侧实色为已用、右侧浅灰为剩余，实色随使用从左向右增长。
- 新增账户前及每次实际额度查询前，检查 https://ip.net.coffee/claude/ 的信任评分；只有大于 50 才继续。有效低分提示网络不达标、无法更新；其余刷新失败使用简洁提示，可建议尝试重新登录，不承诺重新登录一定解决。无法取得有效评分也阻止操作，不伪造低分，不向用户展开技术报错。
- 主动刷新指用户点击刷新；被动更新以后台每 30 分钟为目标，由 iOS 尽力调度，不承诺准点执行。打开或回到 App 时立即自动刷新，独立于上述周期；不提供刷新频率设置。
- 账户默认按添加顺序排列，允许手动移动并保存顺序；重复登录同平台同邮箱时，以最新成功登录去重，新登录未成功前不删除旧账户。重新登录账户 1 仍为账户 1 时更新凭据；登录为账户 2 时直接显示账户 2，默认替换原位置，不增加身份差异确认。
- 授权已形成有效绑定但首次额度查询失败时，保留待获取账户并允许重试；不伪造额度或成功时间，新增前网络检查未通过或授权未完成时不创建账户。
- 小组件提供小号和中号，所有实例固定展示当前账户列表第一项，不提供选账户操作；重排或删除后跟随新的首项，无账户显示“未连接账号，无数据”。两种尺寸展示平台实际提供的周窗口与 5 小时窗口、剩余额度、重置时间和最后成功更新时间。
- 添加教程保留简单动画及可独立阅读的文字，说明添加和选择尺寸，删除选择账户步骤；账户显示由列表首项决定。
- App 自动跟随手机系统切换浅色／深色；视觉采用参考 Nowdex 布局的黑白灰简洁卡片，原型已提供完整两套外观。
- 第一版不做电脑 token 历史、费用和趋势统计，不接入 Tokens.ci，不要求用户安装电脑采集器。
- 用户使用自己的第三方平台账户；目前不计划建立本产品的注册登录系统。
- 优先探索无需自建后端服务器、由 App 直接查询平台余量的方案。
- 以通过 App Store 发布为目标，暂按已有 Apple 开发者账号进行规划，实际会员状态在发布准备阶段核实。
- 复用已有项目的登录与额度查询能力；已有技术项目不等于本 App 在 iPhone 上的连接、授权保存及真实查询已验证。13 平台连接方案研究用于技术准备，不成为 MVP 全部接入的交付承诺。

## 研究结论

参考产品已识别为 Nowdex。它的订阅额度查询与历史 token 统计是两条不同链路：前者由设备向平台查询；后者通过电脑 Tokens 采集器上传汇总，再由手机读取 Tokens.ci。不能把“不自建业务后端”理解为“不使用任何云端服务器”。

详细证据、开源项目用途、数据流和实施方案见 [Nowdex 实现研究](docs/nowdex-research-2026-10-08.md)。

## 后续待验证与决定

- Codex 在 iPhone 上的账户连接、授权有效期、安全保存与真实额度查询，需要结合已有技术能力完成端到端验证；其他平台留作扩展研究。
- 真实支持的套餐和额度窗口、最低 iOS 版本、正式产品名称；原型已覆盖小号和中号主屏幕小组件，采用黑白灰浅深双外观。
- 同平台多账户已纳入第一版；具体授权隔离、网络评分获取与实际网络对应方式留到实现阶段验证。
- 后续再确定上架地区、收费方式与语言范围；iCloud、锁屏小组件和低额度预警不纳入当前必做范围。

## 初步可行性判断

无自建后端是待验证的方向，而非已确定的结论。没有本产品的注册登录系统，仍然需要安全处理第三方账户授权、凭据过期和重新绑定。

CodexBar 的电脑端功能部分依赖浏览器登录状态、命令行工具和本地文件。iPhone App 不能直接照搬这些读取方式。首版 Codex 需要验证能否在目标设备完成授权，以及能否直接取得真实订阅余量。普通 API 余额与订阅额度也需要分开判断。

参考来源：[CodexBar 项目说明](https://github.com/steipete/CodexBar)、[Apple 应用隔离机制](https://support.apple.com/guide/security/security-of-runtime-process-sec15bfe098e/web)。
