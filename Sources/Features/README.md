# 页面落点

`QuotaView.swift` 为额度无账户／已绑定身份页面及顶部操作，`SettingsView.swift` 为设置分组入口；`Sources/App/RootView.swift` 组装底部导航及共享连接弹层。

T07 的三个连接按钮共用 `CodexConnectionFlow`：新鲜网络检查、申请一次性代码、安全保存临时事务、主动复制和系统默认官网打开。低分／未知不申请，取消阻止迟到结果，重试等待旧工作结束；T08 增加本次事务的结果领取、核验与正式账户保存；核验失败不写账户。T09 在本次进程内复用仍有效的轮询或已领令牌；T10 在启动时读取原事务并从领取、未兑换代码或待核验令牌继续，重复启动读取合并为一次；取消、明确失败、交换不明与到期结束旧流程并清理短期材料，重试重新检查网络。`CodexConnectionView` 负责简短反馈和代码步骤，采用系统浅深颜色，等待／失败为轻量弹层。

`CodexConnectionUITestSupport` 仅在 Debug 且显式参数下启用：隔离 UI 场景使用固定数据、内存替身和专属临时文件；T09/T10 live 参数使用生产网络/官方核验，但账户与钥匙串按严格 UUID 独立保存，不触碰正式账户。没有产品开关或菜单，Release 不包含这些入口。当前仅首账户；T12 在绑定成功后独立自动查询并显示平台套餐；有适用额度时显示两窗口剩余、真实重置与成功时间，确认 Free 无本期适用额度时只显示身份和套餐，失败仍保留可信资料；暂禁再次连接，重复连接/多账户由 T16/T18 接入。其余未接入操作仍禁用。完整分工见 [项目结构](../../docs/project-structure.md)。

T10 在后台不开始新的领取／兑换／核验／保存步骤；正在接收的结果先安全保存，回前台由原工作继续，不承诺后台持续执行。正式账户前台额度刷新仍属于 T27。T10 UI 样例用专属 Application Support 路径及真实独立 Keychain 验证进程重开；真实验收另用 T10.live.UUID，不混用样例。

T12 在加载原有未获取额度或缺独立套餐资料的首账户时自动完成首次查询，避免升级后强迫用户重登。已有完整套餐与成功结果（含无适用额度）直接读回；每次回前台刷新仍由 T27 实现。登录弹层关闭不取消独立额度查询。首次失败显示“获取失败”，原有结果更新失败显示“刷新失败”，有效低分仍显示“网络不达标，无法更新”；不叠加“尚未获取额度”占位。普通 hosted 单元测试的主场景使用空的隔离流程，不会因主页面出现而隐式查询正式账户；真实验收需测试显式组装。
